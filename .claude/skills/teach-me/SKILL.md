# Teach me my own code

The user is a beginner (CS50) who wants to be able to explain their game's code to a recruiter.

1. Ask nothing up front. Pick the part they named, or the change you just made.
2. Explain it in plain language, in this order:
   - What it does in the game (what the player sees).
   - Which file and function it lives in, with the 5-15 most important lines quoted.
   - How it works step by step, one short paragraph per step. Define any new word (e.g. "instancing", "shader", "tick") the first time it appears.
   - Why it was done this way, and one alternative.
3. Give a tiny hands-on exercise they can do themselves in under 5 minutes (e.g. change a number and see what happens in the game), and tell them what they should see.
4. End with 3 quiz questions, from easy to harder, one of which is "how would you explain this in an interview?". Wait for their answers, then mark them kindly and fill the gaps.
5. Don't change any code yourself during this skill unless they ask.
